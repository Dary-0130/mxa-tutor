**目标**:诊断显示 build_steps 降级主因 = LLM 省略 `block_refs[*].paper_reference` 触发 dto_invalid(10/13 字段错、finish_reason 全 stop、非截断)。本卡把 draft 输入容错与既有公共/域语义对齐:公共契约本就允许该字段为 null、下游本就按 None 处理,**唯独 draft 解析层逼 LLM 必须显式写 null**。让缺省合法解析为 None,消除该主因、让 build_steps 生成率回升、主路能真跑到 528 指导层。

**非目标(明确不做)**:
- 不改公共/域/导出契约的 requiredness(§6)。

## 2. 诊断依据 + 已核实代码事实(本卡设计据此;R6 前次只读核查坐实)

**诊断(真机 3 篇 × 3 轮 = 9 次完整主路、真 DeepSeek)**:build_steps 降级 4 次;dto_invalid 的 13 个 Pydantic 字段错里 **10 个 = `block_refs[*].paper_reference` 缺失,finish_reason 全 stop(非截断)**。→ 主因既非模型偶发噪声、亦非输出截断,而是该字段缺省。(另:9 轮里 2 轮未到 build_steps 即终态,均 `plan_composer invalid_json + finish_reason=length`;主路跑到 528 指导层 2/9。)

**已核实代码事实(Codex 对真仓库)**:
- draft 的 block_refs **复用公共 `StepBlockRefModel`**;`StepBlockRefModel.paper_reference: PaperEvidenceEntryModel | None` **无 `default=None`** → Pydantic「required 但 nullable」:显式 `"paper_reference": null` 能过,**缺 key = `missing`**;`dto_invalid` 由 `_BuildStepsOutputModel.model_validate` 的 `ValidationError` 转 `BuildStepsDtoValidationError`。
- 域 `StepBlockRef.paper_reference: PaperEvidenceEntry | None` 语义允许 None;导出 TS `paper_reference: PaperEvidenceEntry | null`、公共 schema required + nullable。
- 下游对 None **已按设计处理**:证据校验只把 `paper_reference is not None` 送 spec 校验;BR 匹配 / coverage 只用 `block_type + purpose`;display_text 派生不读 paper_reference;guidance 证据池 `if entry is None: return`;coverage 把无出处块记 uncovered(设计内)。
- **结论**:bug 只在「LLM 原始 JSON → 私有 draft DTO」这一层;公共契约、domain 语义、下游消费层均无需改。

## 3. 核心原则(不得推翻)

### 3.1 修复落 draft 层,不改公共契约
容错放 draft 层(LLM 输入边界),只修输入适配。公共 schema「required + nullable」对消费者有价值(字段稳定存在、值 null 表无出处),**不得为迁就 LLM 解析翻成 optional**。给 draft 的 `paper_reference` 一个 `None` 默认 = 语义对齐,不是语义放宽。

### 3.2 只容忍「key 缺省」这一件事,红线/证据不放松
draft 容忍的**仅**是缺省。非空 paper_reference 仍走既有 locator/source/excerpt 校验;user_supplied 仍一律拒(初始生成无 resolved record);无法解析到唯一 locator 的 evidence 仍丢弃/重校验/按需 fail;红线机检一条不动。缺省 → None,**None 不是证据、不进 document_extracted 证据链**。

### 3.3 缺省 → None → public JSON `null`(装配显式构造,不漂移)
LLM 可省略,系统内部归一成 None,但对外仍输出显式 `"paper_reference": null`。装配 draft → 域对象时**显式构造**公共/域 `StepBlockRef`;持久化/响应一律走公共 domain/wrapper dump,**严禁把 draft dict 直接塞进 plan_json**(否则缺省 key 原样持久化、隐性破坏 public/TS shape)。

## 4. 做什么(必须做)

1. **draft 层容忍缺省(首选:私有 draft block-ref 模型)**:build_step_planner 的私有 draft **不再复用公共 `StepBlockRefModel`**;新建私有 draft block-ref 模型(如 `_StepBlockRefDraftModel`,`paper_reference: PaperEvidenceEntryModel | None = None` **带 default**,`extra="forbid"`,**其余字段名/类型与公共 `StepBlockRefModel` 逐一对齐**),使 LLM 省略该 key 合法解析为 None。放 `paper_plan_service.py`,不进 `OUTPUTS`/export。
   - **备选(仅私有模型不干净时)**:补 null 窄预处理——**只**在解析成 dict 后定位 `build_steps[*].block_refs[*]`、**且仅当缺 `paper_reference` key** 时补 `null`。**严禁**递归给所有 nullable 补 null、**严禁**碰 `PaperEvidenceEntry` 内部字段、**严禁**补任何其它 missing 字段、**严禁**改 extra 行为(其它 missing / 多余字段一律留给 Pydantic 照常报错)。
2. **装配不变**:draft → 域对象时,None 照常显式构造公共/域 `StepBlockRef`,序列化出 `"paper_reference": null`。11 条校验、display_text 派生、证据双源全部沿用现状(本就吃 None)。
3. **红线/证据不放松**(§3.2):非空 paper_reference 仍全套校验;user_supplied 仍拒;红线一条不动;缺省块走 coverage 既有「未 covered」路径,**不豁免、不补造来源、不转成任何 evidence**。
4. **coverage 语义钉死(不新增字段)**:`paper_reference is None` 的 block_ref **计入 build_steps 有效结构**,但在 paper-reference coverage 里**记为 uncovered**;**不生成 evidence、不降级为 invalid、不从 coverage 分母静默剔除**。**本卡不新增 `uncovered_reason` 之类分类字段**(要更细的 coverage 分类另起卡,见 §7 K4)。
5. **脱敏诊断计数(内部,元数据 only)**:加「omitted → accepted」脱敏计数(stage / field path / reason code / count),便于下次同类回归定位。**只记机器元数据,禁 raw JSON / prompt / 字段值 / LLM 输出 / 异常 message / traceback**(决策 11)。**纯内部,不进任何对外 DTO/schema/TS。**
