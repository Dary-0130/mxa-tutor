## 1. 目标与范围
把活动内容闸从「整份 PDF 原始字节搜三个子串、命中即拒」改为「基于 pypdf 规范化对象图、只放行明确验证安全的本地导航动作,其余一律 fail-closed 拒」。**对外错误码 `active_pdf_content_not_supported` 不变**;内部新增脱敏子原因码(不进对外契约)。**不做 PDF 消毒/剥离危险动作后放行**——危险即整篇拒,那是独立设计。

**判定基础(硬约束)**:全程基于 pypdf 已规范化的对象图(自动解开间接引用 / `/ObjStm` 压缩 / `/Prev` 增量更新最新有效版 / name `#xx` 转义)。实现统一用 `obj[key]` 或显式 `.get_object()`,**禁裸 `dict.get()`**(R6:`dict.get()` 不走 pypdf `__getitem__`、返回未解引用的 `IndirectObject`)。**destination array 元素不自动解引用,page ref 要显式 `.get_object()`**(R6 补坑)。

## 2. 两套发现机制(★ R1 P0-2:必须分开,不能只做 A)

### A. Action-root collector(收集所有动作入口,逐个判 `/S`)
完整收集以下入口的动作字典:
- catalog `/OpenAction`
- catalog `/AA`、page `/AA`、annotation `/AA`、form field `/AA`
- annotation `/A`
- outline `/A`(★ 手挖 raw `/Outlines` 树:从 catalog `/Outlines` 沿 `/First`/`/Next`/子级可达的真实 outline item 的 `/A`;**禁用 `reader.outline` 视图**——R6:它把 outline 弱化成 destination 视图、非 `/GoTo` 会被抹掉,不能作安全判据)
- **page `/PresSteps`(★ R1 P0-1 新增):v1 最窄策略 = 任意当前有效页面存在 `/PresSteps` → 整篇拒为子原因 `pdf_subpage_navigation_unsupported`**(不遍历 navigation node、不新增放行上下文)
- 任意动作字典自身的 `/Next`

对每个收集到的 action root:仅上下文白名单中的动作可放(见 §3);其余 `/S`(含未知、私有、缺失、非 Name 值)一律拒。

### B. Non-action active-object detector(★ R1 P0-2:粗粒度「在不在」探测,探到即拒)
以下非动作型活动对象**不长动作的样子、不会自己落入「默认拒」,必须主动探测存在性**;探到即整篇拒,**不要求精细解析内容**:
- catalog `/Names`→`/JavaScript` name tree(文档级自动脚本)→ `pdf_document_javascript_name_tree`
- AcroForm `/XFA` → `pdf_xfa_present`
- 3D stream `/OnInstantiate`(直接挂在 3D stream 上的脚本流,非 `/S /JavaScript`)→ `pdf_3d_script_present`
- RichMedia / Screen / Movie / Sound 媒体对象 → `pdf_active_media_present`
- 嵌入/关联/附件文件:filespec `/EF`、catalog `/EmbeddedFiles` name tree、`/AF`、`/FileAttachment` annotation → `pdf_embedded_file_present`

**实施修正(合并前复跑补):Non-action detector 只按上述规定入口定点探测,不得从 catalog 全对象图递归翻找任意 key。全图递归会把正文、字体、图像、外观流等无关对象卷入预算,误拒正常论文;危险对象入口仍按本节枚举 fail-closed。**

## 3. 放行白名单(须全部满足,否则拒)
- catalog `/OpenAction` 为有效当前文档 destination array;或 `/S == /GoTo` 且 destination 解析到本文档 page tree 内的页/命名 destination、且无 `/Next`;
- annotation `/A`:**★ 完整谓词(R1 P1-2)** = `/Subtype == /Link` AND `/A` 是动作字典 AND (`/S == /GoTo`(同上目标约束) OR `/S == /URI`) AND `/A` 无 `/Next` AND 该 annotation 无 `/AA` AND(URI 时)`/URI` entry 存在且类型合法。**禁写成「任意 annotation `/A /S /URI` 放行」**(Screen/Widget 也能挂 `/A`;负例:`/Subtype /Widget` + `/A << /S /URI >>` 必须拒);
- outline `/A`:`/S == /GoTo`,同上目标约束,且仅限 §2.A 那条 raw `/Outlines` 可达路径找到的真实 outline item;
- 无任何活动内容。

**`/GoTo` 目标验证(fail-closed)**:destination 三形态——array 用 `reader.pages` 的 page indirect id 集合校验第一项确指向本文档页;name/string 用 `reader.named_destinations` 解析再映射 page number。**禁盲用 pypdf 私有 `_build_destination()` 宽松 fallback 作唯一判据**(R6:坏 fit 下可能仍给 page 0);解析不到本文档内 → 拒(`pdf_internal_destination_unresolvable`),**不猜**。

## 4. 拒绝清单(任一命中整篇拒,不降级不剥离)

- `/Launch`(★ 含单独出现、不伴 `/OpenAction`/JS 的——补现有漏洞;**任意入口**出现 `/Launch` 都走「非白名单 action type → 拒」,不只 annotation);

- **自动/被动事件触发的 `/URI`**(打开自动跳外网址——产品方已拍板拦);绝对/相对/`file:`/自定义 scheme 一律拒,不解析/不记录真实地址;
- 任意 `/AA`(v1 整拒);任意 `/PresSteps`(v1 整拒);任意动作带 `/Next`(v1 拒为 unsupported);

### 4.1 ★ 解析修复信号契约(R6 第7条 + R1 P1-4:两边合出,必须落实)
pypdf 6.13.2 默认 `strict=False`,对坏 startxref / xref 重建 / 找不到对象 / Root 恢复等**可能记 warning 后静默修复继续、不统一抛异常、无 `reader.repaired` 属性**。**禁在库私自修复过的对象图上做安全判定而不自知。** 二选一落实(实施时选定并在 PR 说明):
- **(优先)安全闸预检用 `strict=True` 专门 reader** 读一遍;并证明本卡回归的正常样本全部通过(见 §6 回归);或
- 适配层捕获全部 parser recovery 事件、转结构化信号 `pdf_structure_unverifiable`。

**信号分三类落实,不靠散落日志字符串判断**:
- 直接可判(现成信号即拒):`PdfReadError`/`ValueError`/damaged parse exception、encrypted PDF、destination 解不到、unsupported action type;
- 需自建预算(实现期设阈值):扫描节点数 / 递归深度 / 动作入口数 / name-tree·outline·form field 遍历上限 / 软耗时预算——超限即 `pdf_structure_unverifiable` 拒;合并前误拒修正后预算取偏松但有限上界(如动作/outline/form 入口 10000 档),主要防真正海量恶意结构,不把正常论文正文对象计入 non-action 节点预算;
- xref 冲突/重复键/部分 damaged repair:按上面二选一捕获,**不能默认 strict=False 下修了 xref 却让闸不知道**。

### 4.2 对象范围(R1 P1-3)
判定以最新有效 revision 的 catalog 为根,只扫从当前 catalog / page tree / outline tree / form tree / annotation / name tree 可达的有效对象。**不遍历/不拒**:xref 里当前不可达的 orphan、已被增量更新覆盖的旧动作、历史 revision 残留但当前不再引用的对象(否则退化成「历史出现过危险词就拒」的全 xref 版)。反过来:当前 catalog 可达、即便来自旧 revision 的对象,仍须检查。

## 5. 遍历安全(R6 第5条 + R1 P1-1)
