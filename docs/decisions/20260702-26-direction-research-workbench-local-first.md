> **日期**:2026-07-02
> **关联宪法**:v3.2 → 本决策生效后需升版(目标用户 / 产品定位 / 数据边界三处)
> **关联决策**:`20260615-22-direction-pivot-paper-to-model.md`(第一次方向 pivot,量级同此)
> **性质**:PM 主导的**第二次方向转向**(单篇复现工具 → 面向学校的科研工作台),量级与「MCS → paper-to-model」相当。单独立决策,不缝进任务卡。

---

## 1. 背景

paper-to-model 单篇复现已整条交付。PM 复盘核心判断:①单篇复现是一次性工具,粘性 / 复购 / 卖相撑不起;研究者真实工作流是「围一个课题、几个月读几十篇、横着比、攒着用」。②买单方是**学校**,要进校园得让机构层看到价值。③核心壁垒(复现 + 参数对应 + 调参 + 举一反三)不变,外面长出「每天打开的科研空间」。

故转向:paper-to-model 从「单篇复现工具」扩展为「**面向学校的研究生科研工作台**」。

---

## 2. 一句话方向

**产品从「单篇复现工具」升级为「面向学校的研究生科研工作台」:研究生每天打开、读论文 / 复现 / 调参 / 举一反三;核心壁垒不变,外面长出科研空间;数据本地优先——用户研究数据的真相源是他手上的本地课题包,服务器只临时计算、24h 清、永不长存。**

---

## 3. 北极星(A · PM 已拍)

- **A1 主力用户**:做课题的研究生(每天打开、泡在里面);本科生一次性复现当兼容场景(现有单篇能力已覆盖)。
- **A2 买单方 = 学校**(★):产品要让学校觉得有价值、愿意推进进校园。**第一版只做学生端、只走叙事**——「数据全在学生本地、服务器什么都不留、实验室数据碰都不碰」本身即进校园最强信任背书(§5)。**不做机构结构**(班级 / 课程 / 老师后台),但预埋最小机构元数据(§7 + §11.3)。**口径诚实**:V1 是「可进校园试点的学生端」,不是「完整学校管理版」;学校价值先用隐私 + 教学效率叙事打开试点,正式采购能力留后续机构层(不把「学校采购」说满)。
- **A3 边界**:先把 **复现论文 + 调参 + 辅助学生举一反三** 做扎实,其余靠用户反馈。**紧扣建模复现主线**,不做通用文献管理 / 写作 / 笔记。

---

## 4. 架构主线:甲(本地优先)· R1 收敛后的准确定义

> **★ 关键收敛(R1 P0)**:甲不是「纯浏览器本地」。准确定义 = **本地课题包文件是真相源;浏览器缓存(OPFS/IndexedDB)只是加速恢复缓存;服务器只是本次分析的 24h 临时计算缓存;轻客户端 / File System Access / Electron 是后续降摩擦的实现通道。**

### 4.1 核心铁律(对学校 / 对用户都讲)
> **你的研究数据真相源是你手上的本地课题包;服务器只在你这次用时临时加载计算,用完 24h 全清、永不长期保存。**

### 4.2 本地课题包 = 活的真相源、随做随更(★ PM 纠正:不是「存一次」)
- 用户长期做课题,数据一直在变(新传一篇 / 改参数 / 追问 / 生成新 plan)——本地课题包**随做随更**,不是开头存一次。
- **硬要求**:「存回本地」须顺手、常态化;**目标 = 活的、自动写回**。
- **实现分层(R1)**:纯网页写本地文件受浏览器限制,V1 网页可能做不到全自动写回,靠「提醒导出更新版」的半自动;真正「随做随存回本地」的无感体验等**轻客户端**。定稿明确:**目标是活的自动写回;V1 网页先尽力(可能半自动),轻客户端再做真无感。**
- **★ 真相源不是浏览器缓存**(R1 P0):清浏览器 / 换电脑 / 机房还原 / 隐身模式都会让缓存消失。真相源**必须是用户可见、可复制、可备份的课题包文件**;浏览器缓存只做「本机快速恢复」。第一次用后须给用户明确动作:保存本地课题包;之后再做「自动打开上次课题包」的无感。

### 4.3 补丁二:跨篇积累先浅后深(PM 已拍分步 + R1 硬约束)
- **第一步(浅,甲下顺做)**:本地论文列表、各自打开、基础检索——不需全库长驻服务器。
- **★ 浅跨篇也必须沿用 `document_id` / evidence / conflict 证据底座**(R1 P0),只是不做综合推理;**不得绕开现有多文档证据模型做自由文本总结**(否则深跨篇返工)。
- **第二步(深,验证后再做)**:跨十几篇比对 / 综合。R1 指明这是**证据模型问题非算力问题**——须先定义「跨篇结论是否有单一出处 / 无单一出处如何展示不挂假 citation / 参数冲突如何保留 / 临时结果是否写回本地 / 服务端 session evidence map 如何 24h 清」,再做。分三层:Library(本地列表+轻检索)/ Compare(临时选 2–5 篇对比、结果写回本地)/ Synthesis(跨十几篇综合,证据桥+冲突展示+无单一出处表达成熟后才做)。

## 5. 三根支柱(为什么选甲)

1. **进校园信任背书(★ 决定性)**:学校对「学生 / 科研数据存谁服务器」敏感度极高;「数据全在本地、服务器什么都不留」几乎消掉最大采购 / 合规障碍。
2. **实验室数据本身保密**:研究生本地实验室数据本就保密,本地存对用户也更好、更被接受。
3. **与项目一贯隐私姿态一致**:项目从立项就锁「24h 清、不长存、不囤、日志不记原文、数据不训练」。甲是**强化**不是推翻。

---

## 6. 隐私铁律(甲下全锁死 · PM 已拍)

- **数据主权归用户**:论文 / 结果 / 课题真相源只在本地课题包。
- **服务器 24h 清、永不长存**——★ **不只清原始文件,还清所有服务端派生产物**(R1 P0):parsed text / 临时 PaperSpec·Plan JSON / prompt context / LLM raw response / vector chunks·embeddings / session cache / upload manifest / error payload / run-state / 日志中任何可复原片段。
- **可完整导出到本地 + 可彻底删除**。
- **绝不跨用户 · 绝不拿去训练**。
- **★ 现状缺口(R6 已核,P0)**:现有 24h cleanup worker 只扫 `project_status_record`,**不覆盖 `paper_spec_cache`/`paper_plan_cache`**——等于论文解析结果现在是留着的。**TASK-522-B 顺手补上论文数据的定时清理**(这对隐私是修 bug、不是加风险)。

### 6.1 数据采集边界(★ PM 已拍:收行为、不收内容)
> **收「用户怎么用工具」(行为),不收「用户在研究什么」(内容)。**
- **可以收**(纯行为 / 数字 / 元数据,不含内容):点了哪些按钮、用了哪些功能、卡在哪步、耗时、成功率、传了几篇、生成几次、报什么错、界面怎么用、激活 / 活跃 / 找回成功率等——用于产品优化 + 学校试点汇报。
- **不碰**(用户实际研究内容):论文正文 / 抽出的文字 / 参数值 / 追问问题正文 / 生成的 plan 内容——一律不进服务器长期采集(仍临时处理完 24h 清、真相源存用户本地)。
- 边界原则写死:**能优化产品的行为数据尽量收,但只要触及研究内容一律不收长期**——防止「能优化就收」被宽泛解读到把论文内容也收了,砸进校园信任牌。

### 6.2 产品文案两层(R1 P0,防责任误解)
- **对学校**:研究数据不长期留在我们服务器。
- **对学生**:你的课题包保存在你本机,请像论文资料一样保管;系统提供导出 / 备份 / 恢复提示。
- **不建议只讲「服务器什么都不留」**,否则用户丢本地文件会认为产品没兜底。

## 7. 账户(B · PM 已拍「要做」,甲下变轻)

- 甲下账户**不存研究数据、不承载存储**,= 轻门禁 + 身份(内测准入 + 标识哪个学校 / 人 + 支撑学校试点汇报)。工程量在甲下小很多。
- **但 R1 提醒**:「找回 / 跨设备」会暗中把账户变重——不是存论文原文,而是持有**元数据**。账户只存(方向草图,字段未冻结):
  ```
  user_id · school_id? · cohort_id? · license/beta entitlement ·
  device fingerprints? · workspace registry 不可逆摘要 ·
  usage telemetry 聚合指标 · consent/privacy acks · last_seen_at
  —— 无 raw paper / 无 parsed text / 无 plan content
  ```
- **内测期**:极轻方案(内测码 / 单账户占位)先验行为,正式登录等试水后定。

## 8. 产品形态(D · 方向已定,UI 细节实施期定)

- **「家」**:本地加载进来的「我的课题 / 论文列表」。按「课题 / 项目」组织可后加,内测先扁平。
- **单篇找回**:本地课题包文件导入 / 导出;随做随更(§4.2);V1 网页先半自动、轻客户端再无感。
- **跨篇**:先浅后深、沿用证据底座(§4.3)。
- **导出文件**:= 用户全部研究数据的本地家 + 找回凭证;V1 **不做共享、不做跨产品**,但**文件内部天然分层**(§11.1)——共享口子不是「未来加字段」,而是格式天生支持按 workspace / project / document / artifact 分区导出。
- **导入 / 导出不是一个按钮**,是状态机(§11.4)——否则前端会把所有失败都做成「请重新上传」,工作台感崩。

## 9. 节奏(E · PM 已拍 + R1 调整试水指标)

1. **先做单篇能力**(TASK-522 解析纠错四条:②重新解析 → ③用户纠错 → ④局部重跑;①诚实提示对内暂缓)。这几条两条路都要用,照旧做完、往工作台留口子,不打断。
2. **再做轻量级工作台试水**:极轻方案让研究生用起来验行为。**★ R1 调整**:样本 2–3 个偏少——2–3 个做深访够,**行为验证至少 8–12 个不同课题方向**,否则被个体习惯误导。**试水指标不只「是否每天打开」**,还要验:是否愿把真实课题放进本地包 / 第二天能否恢复 / 换设备能否恢复 / 是否理解「服务器不保存、文件自己保管」/ 是否主动攒第 2·3·5 篇 / 是否回看旧 plan / 是否把调参带回 MATLAB / 是否产生举一反三问题 / 导入导出摩擦是否致放弃 / 是否需跨设备 / 是否需共享。**数据恢复成功率必须进指标。**

- **第一版只做学生端**(PM 确认):老师 / 机构视角等真进校谈单再加。

## 10. 甲之外的取舍(R1 审 + PM 拍:选甲、不焊死回退)

- R1 不建议改乙(服务器受控长存)——学校方向下乙直接打中采购阻力,且甲更贴项目一贯红线。
- **PM 拍:默认甲、V1 不做受控长存;但文件格式 / 账户 / consent / workspace policy 预留「未来受控同步 / 学校私有部署 / 用户显式云备份」的迁移位**——产品承诺选甲,技术不焊死乙的回退路径。
- 可接受的未来回退(均单独决策、不在 V1 暗加):①用户显式云备份(默认关、主动开、明示存什么存多久);②学校私有 / 校内部署(采购单独谈);③只同步索引 + 元数据(不含原文 / 完整 plan)。**V1 不暗加「受控长存」字段**,否则学校叙事含混。

## 11. 三个预埋契约(★ R1 P0:本地优先的技术含义须从口号收敛成契约;此处**锁原则、不冻字段**,落地在工作台试水阶段)

### 11.1 LocalWorkspaceVault v0(本地课题包)
本质是**本地单用户数据库**,不是随手 JSON。方向草图:
```
mxa-workspace.mxa
├─ manifest(format_version / workspace_id / app_min_version / created_at·updated_at / owner_hint? / school_hint? / capabilities)
├─ documents/DOC-xxx(original 或 encrypted / parsed_text / assets)
├─ artifacts(paper_spec.json / model_generation_plan.json / tuning.jsonl / qa_threads.jsonl / user_supplied_params.json)
├─ indexes(lightweight_search / embeddings 可选、V1 不必带)
├─ audit(source_map / evidence_links)
└─ integrity(checksums / optional_signature)
```
**硬约束(原则锁)**:workspace_id ≠ server session id;所有 artifact 带 schema_version;所有 document/evidence 沿用 `document_id`;所有用户补充保留 `source=user_supplied`;**支持局部共享(按 workspace/project/document/artifact 分区)不只全包**;支持迁移、旧文件不立即废。**安全**:单文件泄露=整课题泄露 / 损坏=整课题损坏 / 发给同学=无意全共享 / 多设备编辑冲突——故 V1 底层须支持分区导出(即使 UI 只给「导出全部」)。

### 11.2 EphemeralAnalysisSession(服务端临时会话)
```
session_id / account_id? / workspace_id hash / uploaded_doc_hashes /
temp_paths / cache_keys / expires_at / deletion_status
```
**R6 验收必须能回答**:哪些目录清 / 哪些表清 / 哪些 cache 清 / LLM raw response 是否存 / embeddings 是否存 / logs 是否可反推正文 / 删除失败如何重试 / 用户手动删除如何触发。

### 11.3 Account / Institution 最小元数据(不上老师端、只预埋)
```
Account: user_id / school_id? / school_email_domain? / beta_code_id? /
         entitlement_source / consent_version / created_at·last_seen_at
Workspace registry: workspace_id_hash / local_only=true / last_opened_at /
         doc_count / artifact_count / no_content_stored=true
最低机构预埋字段(不改 V1 形态、免后面从用户/usage/license 表重写):
  school_id? · cohort_id? · course_id? · teacher_ref? ·
  workspace_policy_version · data_residency_mode=local_first ·
  consent_version · entitlement_source(beta_code|school_pilot|individual)
```
**只存元数据、不破甲**;支撑内测统计 + 学校试点汇报。

### 11.4 Import/Export UX 状态机(方向草图)
```
NoVault / VaultSelected / VaultCached / VaultDirty / VaultExportNeeded /
VaultMissing / VaultCorrupted / VaultVersionUnsupported / ServerSessionExpired
```

## 12. 学校采购现实(R1 落地提醒,定稿口径)

- 「服务器不留」是强背书但非完整采购理由;学校还会问教师可见性 / 课程用途 / 成果导出 / 离校数据归属 / 管理后台 / DPA·隐私协议 / 本地丢失担责——**V1 诚实定位为「可试点的学生端」,正式采购能力留后续**。
- 学校最关心的可能是「学生不会把实验室数据传给外部服务」。故除「服务器不留」外须能说清:临时上传目的限定(只为本次请求)/ 第三方模型边界 / 可审计删除(有制度 + 技术说明)。
- 本地优先降合规阻力但升支持成本(学生找不到 / 版本不兼容 / 缓存与包不一致 / 误删 / 机房权限 / 多端不一致 / 网盘同步冲突)——内测须记数据恢复成功率。

## 13. 与既有承诺一致性检查(R1)

- **与「副驾不替代」不冲突**,但「工作台」文案须防过度承诺——避免:自动完成科研 / 自动复现 / 自动生成可运行模型 / 替导师答疑 / 替写论文 / 课题管理全平台。
- **与三条可信度红线一致**,但工作台放大执行压力(多篇 / 多次补充 / 多轮调参,证据混乱概率高于单篇)——上层不得为快复用 overview/explanation 私有结构,跨 feature 共享只经 `core/` contract 层。
- **与隐私姿态一致**(强化),但服务端临时缓存须可证明——由 R6 核实现状,不只写原则。

**对学校讲的那句「服务器 24h 全清」,主体是实的。**

### 2. 但发现两处边界(★ 记账,不粉饰)

**(a) 数据库层没有结构性保护。**
`paper_plan_cache.paper_id` 与 `paper_parameter_correction.paper_id` **没有外键指向 `paper_spec_cache`,没有 `ON DELETE CASCADE`**。

清理是**按论文主档走的**:先选出过期的 `paper_id`,再删挂在它名下的行。
→ **主档若先没了,附属行就没人认领,且永不过期。**

**(b) 一条会漏的路径(哑口子,当前无生产入口调用)。**
`invalidate_spec()` 删了 `paper_spec_cache` / `paper_plan_cache` / `paper_reparse_source_cache` / `paper_upload_job`,**唯独没删 `paper_parameter_correction`**。
→ 在已有参数修正的论文上调用它,会留下**孤儿参数修正行**。

★ **为什么这条要紧**:`paper_parameter_correction` 存的是 `original_value` / `corrected_value` / `param_key` —— **用户亲手填的参数值**,正是本决策 §6.1 明写「一律不长期存」的那类**研究内容**。孤儿行 = 服务器上一份永不过期的用户研究内容。

**(c) ★ 老实交代一个无效读数。**
入仓当日直接数了本机库的孤儿行:结果为 0。
**但这三张表当时全是 0 行 —— 空表当然没有孤儿。这个读数在「有 bug」与「没 bug」两种情况下完全一样,不构成任何证据。**
真正的结论只能来自**结构**:没有外键、没有级联、有一条会漏的路径。

### 3. 处置

已记为待办小活(尚未起卡):

1. `invalidate_spec()` 补删 `paper_parameter_correction`
2. **清理 worker 加一道「孤儿扫除」**:`paper_id` 在 `paper_spec_cache` 里找不到的附属行,一律清
   ★ 这是**路径无关**的兜底 —— 将来任何新的删除路径漏了,它都兜得住。**能让机制管住的,别指望人记得住。**(同决策 27 的道理)
3. (另议)schema 加外键 + `ON DELETE CASCADE`,使孤儿**结构上不可能**。需表重建迁移,单独评估。
