## 背景

### 1. 那把烂尺子

**同一套指令、同一个模型(指纹完全相同:`fp_8b330d02d0_prod0820_fp8_kvcache_20260402`)、同一批 8 篇论文,三跑:**

| 批次 | 端到端成品率 |
|---|---|
| 第一批 | 8/24 = **33%** |
| 第二批 | 13/24 = **54%** |
| 第三批 | 15/24 = **63%** |

**什么都没改。**

**★ 我们过去所有「改前 vs 改后」的结论,全建立在这种跨天口径上。**

### 2. 同一个病的三个变种

病的本质不是「跨天」,是**「拿来比较的两个东西,其实不是同一个东西」**。它至今出现过三个变种:

| # | 变种 | 怎么发现的 |
|---|---|---|
| 1 | **模型可能悄悄换版** | 供应商模型是预览版、正式版转换就在同周、**模型 ID 不变** → 跨天对比可能是在比两个不同的模型 |
| 2 | **时段 / 上游漂移** | 上游材料每轮重生成;同篇跨轮本身就波动 |
| 3 | **★ 测量通道与生产不同构** | 2026-07-12 只读核查:评测跑道给建模指导层的 **token 上限是 6000,生产是 8000**;**超时是 90 秒,生产另有其值**。**尺子和产品跑的不是同一条跑道**,而它苛刻的地方恰好是当时准备打的那一类失败 |

★ **变种 3 不是孤例:一次核查就照出两项(token 上限 + 超时),且历史评测产物里白纸黑字写着 `max_tokens=6000`。**
如果不把「测量通道必须与生产同构」写成规矩、并要求**在 provider 边界逐项比对**,还会有第四个。

### 3. 单批数会骗人

「写爆」这一类失败,在三批里分别是 **28 / 13 / 10** 次。
架构师曾据**单批**数排过一版靶子顺序,已作废。**48 轮的分布才作数,单批不作数。**

### 4. ★ 同词异义已经在仓库里发生

TASK-534 as-built **同时记了两个数**:

| | 改前 | 改后 |
|---|---|---|
| build_steps 结构化成功 | 10/24 = 41.7% | 10/24 = **41.7%** |
| 严格成品(build_steps 成功且 guidance generated) | 10/24 = 41.7% | 9/24 = **37.5%** |

**决策 27 引的是宽的那个,并称之为「成品率」。同一个词,仓库里两个数。**
且同批数据里 **guidance 有 14/24 轮根本没触达** —— **指导层的失败率一直是在一个从未被报出来的小机会基数上算的。**

**★ 指标名字不唯一 + 坏事件没有分母 = 实施者可以合法地挑一个好看的数。这本身就是一种烂尺子。**

## 决策

### 1. 效果断言只认同场配对

**「同场配对」的定义**(不得走样):

- **同一次运行**
- **同一份上游材料**(不是「同一批论文」,是同一次生成出来的那一份)
- 把要对比的那一段调用**两次**(旧臂 / 新臂)
- **两臂顺序按轮翻转**(消掉顺序效应)
- **只把新臂送下游**(不污染主路)

现成台子:`--paired-build-steps` / `--paired-build-steps-full`(eval-only)。**★ 这是资产,不许拆。**

**跨天对比降为线索,不再是证据。**

### 2. 判据必须预登记

**阈值 / kill-switch / 守门项,全部先于看数说死。**

- **事后调阈值找补 = 本批数据作废。**
- **测的是哪一版字,合的就是哪一版字。** 通过之后不得「把措辞收拾一下再合」——改了字,等于把刚买来的证据作废。

### 3. 承重墙自证(跑之前,五分钟)

跑之前把两臂**各自最终送进模型的完整文本** dump 出来、diff、贴哈希。
**若 diff 为空 → 实验根本不成立,停手。**

### 4. ★ 测量通道必须与生产同构

- 评测跑道的**有效配置必须与生产同源**,**不得在评测侧自带一套默认值**(手抄的数值一定会漂)。
- **★ 必须在 provider 调用边界比对,不许只比构造对象。**
  只比「配置对象上写着 8000」是能被骗过去的:对象写 8000,下游 wrapper 又改回 6000,diff 依然漂亮。
  **做法**:同一个 recording fake provider、两条构造路径(生产 / 评测),抓它**实际收到的 request**,逐项比对:
  `model` / `max_tokens` / `timeout` / `response_format` / `temperature`·`top_p`·`seed` / 重试次数与上限 / wall clock / prompt·template 版本。
  **★ 禁两套 fake 各自自证自己。**
- **每次运行必须落档、可 diff**:上述全部 + **模型指纹**(每次 provider call 各落一次;summary 落去重集合 + 次数;集合 size > 1 → 不得合并选靶)+ `git_revision` + 静态模板 hash。
- **★ 对齐口径 ≠ 改药。** 把评测拉到与生产同源,是**摆正尺子**;改动**生产**的取值,是**改药**。两者必须在同一份 PR 正文里分清楚,不许混说。
- **★ 也不许把「摆正尺子之后数字变好」说成「产品变好」。** 生产本来就跑在那个配置上。**变的是我们对产品的认识,不是产品。**

### 5. ★ 指标口径冻结(禁止无修饰的「成品率」)

**「成品率」一词,自本决策起在任何卡、任何 PR、任何决策文档中禁止单独使用。**

产品结果**一律分档报,不得压回一个数**:

```
交付率        = 出得来的轮数 / 总轮数
证据干净率    = 出得来 且 无「未核实、推回用户确认」条目 的轮数 / 总轮数
完全可执行率  = 证据干净 且 无阻塞缺口 的轮数 / 总轮数
```

**★ 能不能见人,看的是「证据干净率」,不是「交付率」。**
一份指导可以有一半条目是「请你自己确认」,照样算交付 —— **它不是虚的,是空的**:该讲的没讲,活推回给学生。

**每个新指标必须在第一次使用时给出确定性定义**(可由确定性字段计算,不靠模型判卷 —— 决策 25)。
**归属不明的指标,不许进任何验收。**

### 6. ★ 坏事件计数必须配机会数与分母

**只报坏事件数、不报机会数与分母,是可以被「少生成」刷漂亮的:**
模型少写内容 → 坏事件自然归零;上游多失败 → 下游根本没机会跑,坏事件也归零。
**数字漂亮,产品更空。**

任何坏事件计数(降级 / 丢弃 / 未核实 / 缺口)**必须同时报**:

- **机会数**:该阶段**实际被调用**的轮数。
  ★ **「有没有真的调过模型」是事实,不是判断** —— **必须用调用记录算,不许用状态码推。**
- **产出分母**:最终产出的条目总数、其中该类条目数。

**★ 硬规矩:该阶段没跑到时,分母与坏事件计数一律落 `null`,严禁落 `0`。**
落 0 会让「**根本没生成**」和「**生成了、一条毛病都没有**」在汇总里长得一模一样 —— **这正是最容易被刷的那个口子。**
任何比率的分母**必须是非 null 的有效轮**,且**必须显式报出 null 轮数**。

### 7. ★ 选靶须折算下游存活;样本独立性须显式检查

#### 7.1 折算

**「哪层失败轮数最多就打哪层」系统性偏袒上游。**
修好上游那些轮次,它们还得**活着穿过下游**才算交付。**上游的收益必须打折,下游不用打。**

```
expected_gain(L) = failures_owned_by(L) × downstream_survival(L)
```

`downstream_survival` **从本批数据自算**,不引入外部先验。
**选靶用折算后的期望交付增益,不用原始失败计数。**

#### 7.2 层归因

**按「第一个阻断的阶段」记账,不按「谁报的错」记账。**
一个下游模块报出「上游没给我东西」,**那一轮不算下游的账**。
**两本账,不得混用**:第一阻断层**用于选靶**;终态报错层**用于诊断**。

#### 7.3 样本独立性

**n 轮 ≠ n 个独立样本。** 8 篇 × 6 轮 = 48 轮,但**一篇论文稳定死在某层,就贡献 6 轮**。

- **必须做 leave-one-paper-out**:去掉任意一篇论文的全部轮次后重算,第一名仍须第一。
- **每批必报**:各层失败涉及多少篇论文 / 每篇各层失败次数 / 第一名是否由单篇贡献。
- ★ **判「分不出来」时,出路是换判据,不是加样本。**
  优先改用与层无关的判据(修同时影响多层的机制),其次按修起来便宜排序。
  加轮数无用(动不了 leave-one-paper-out);加论文是另一件事 —— 样本覆盖面属冷启动准入(决策 24:≥20 真实样本),不是选靶前提,归「开测前」那一包。
- ★ **本门的作用是禁止在数据由单篇撑起来时硬选靶,不是触发样本扩容。**

### 8. 单批数不作分布结论

分布结论**至少 48 轮**。
**若两个候选的差距落在已坐实的抖动量级内 → 判「分不出来」,不得硬选。**

### 9. 复跑不是因果证明

判定只许写「**达到预设工程门槛,具备合并资格**」。
**不许写**「假设成立」「机制成立」。(n 有限、同篇跨轮相关,统计功效有限。)

## 适用范围(边界,防扩大化)

**适用**:一切**模型行为效果**断言 —— 交付率、失败分布、某类错误是否减少、某句措辞是否奏效。

**不适用**:**确定性验收** —— schema export 零 diff、单元测试、命门测试、**硬契约按决策 25 由确定性规则验证**。
**这些不触发配对跑。**

*(例:一张只补数据库清理的隐私卡,验收全是确定性测试,与本决策无关。)*

   - 跑在与生产**不同构**的跑道上(token 上限 6000 / 超时 90);

3. **依赖措辞卡的「24 修 0 坏」不受影响** —— 它本来就是同场配对口径拿到的。**这正是它站得住的原因。**

4. **以后任何声称「提升 / 不劣化交付率或失败分布」的卡**,验收必须附:
   **同场配对数据 + 预登记判据 + provider 边界的有效配置比对 + 机会数与分母 + 折算后的期望增益**。**缺一不合。**

## 验收(怎么证明遵守了本决策)

任何做**效果断言**的卡,必须给出:

1. 配对口径说明(同一次运行 / 同一份上游 / 两臂翻转 / 只送新臂下游)
2. **判据预登记的原文**(时间上先于数据)
3. **承重墙自证**:两臂送模文本的 diff / 哈希
4. **provider 边界的有效配置比对**:一个 fake、两条路径、抓实际请求、逐项相等 —— 贴输出
5. **指标分档**:交付 / 证据干净 / 完全可执行,三档分别报
6. **机会数与分母**,且未跑到的轮次落 `null` 不落 `0`
7. **层归因按第一阻断层** + **折算后的期望增益** + **leave-one-paper-out 结果**
8. 结论措辞合规:只写「达到预设工程门槛」,不写「机制成立」

## 理由

### 1. 烂尺子比没有尺子更坏

没有尺子,人知道自己不知道。
**烂尺子让人以为自己知道。**
我们据一把烂尺子排过靶子、下过「方向不对」的结论,都被自己的对照组当场打脸。

### 2. 抖动本身就是敌人,比平均值更要命

产品水位不是「五成」,是**一个 33–63 的区间**。
**学生今天用着好、明天用着坏 —— 这比水位低更劝退。**
只认同场配对,顺带把抖动摆到台面上,而不是让它继续假扮成「改进」和「退步」。

### 3. 三个变种同一个根

「模型悄悄换版」「时段漂移」「测量通道与生产不同构」——
**都是「拿来比较的两个东西其实不一样」。**
规矩必须写在这个根上,而不是逐个变种打补丁。否则一定有第四个。

### 4. ★ 会被刷的指标,一定会被刷

不是因为谁想作弊,而是因为:
**没有分母的坏事件计数,天然奖励「少做事」;名字不唯一的指标,天然奖励「挑好看的那个报」。**
本决策 §5 / §6 不是记账洁癖,是**堵住两条会自动把产品推向更空的激励路径**。
