# 决策 27: 草稿契约与成品契约必须分离

## 状态

✅ 决议(2026-07-12,数字已验证)

## 背景

同一个坑踩了六次,直到第六次才被量化。

| # | 现场 | 症状字段 |
|---|---|---|
| 1 | 507-B | `display_text` |
| 2 | 529 | `paper_reference` key |
| 3 | 2410 | `paper_reference` 内层字段 |
| 4 | — | `abstract` max_length 误伤 |
| 5 | 2605 | `unit` string_too_short |
| 6 | **534** | `paper_reference.source` / `document_id` / 动态 key |

**第六次的代价被量化了:** 8 篇真论文 × 3 轮 = 24 轮真机主路,成品率 41.7%。13 次降级里 **7 次死于此** —— **主路成品率的头号杀手**。

**完整死法**(R6 逐条核实后才拼全,四步):

1. 后端把证据白名单端给模型时,连 `document_id` / `locator` / `excerpt` 一并暴露 —— **等于把答案抄在卷子边上**
2. 模型照抄进 `paper_reference`
3. bridge 遇到对不上的引用,返回 `_DROP_EVIDENCE` **静默丢项** —— 比报错更坏:线索一起删了,诊断查不出具体错在哪
4. 公共 DTO 校验失败 → **整份 build_steps 报废** → 下游建模指导连坐

三件事同一个根:**让模型碰了它不该碰的东西,还在它碰错时不出声。**

★ 根子不是哪一步犯浑,是**从来没人画过一条线:哪些字段归模型答、哪些字段归后端盖章**。线没画,默认就是全给、全要。

## 决策

### 1. 责任划线(前置动作,不划线不许写 DTO)

任何"LLM 产出结构化内容 → 后端补全 → 校验"的边界,**每个字段必须先明确归属**:

- **模型答的**:模型有能力、也有依据回答的
- **后端盖章的**:出处、ID、定位、原文摘录、版本、时间戳 —— 模型答不出、也不该答的

**没有第三类。归属不明的字段,不许进任何 DTO。**

### 2. 草稿 DTO 私有、`extra="forbid"`、后端字段根本不出现

- 草稿模型是**私有类型**,不是公共成品模型的复用或子类
- `extra="forbid"`:模型多给了后端字段 → **显式报错**
- 后端字段**根本不出现在草稿 schema 上**

★ **不许用 `optional` 代替私有模型。**
`required-but-nullable` 改成 `optional`,只是把**硬失败**换成**软伪造**:模型照样会填,填错的值照样进系统,只是不再报错了。**这比原来更坏。**

### 3. 后端字段一律后端自己盖章,不读模型给的任何值

模型只给**一个不透明的引用号**(如 `source_ref`)。后端**按号自己解析**,自己新建完整记录。
**模型给的任何出处信息,一律不读、不采信。**

### 4. 中间解析必须 fail-closed,禁静默丢弃

未命中 / 歧义 / 类型错 → **显式报错**,且**子码可区分**。

禁 `_DROP_EVIDENCE` 式的静默丢项。**静默丢弃比报错更坏**:症状消失了,线索跟着一起没了,病灶永远查不出来。

★ 子码必须能分辨"**真救回**"与"**换个名字接着废**"。**不许把重分类当救回。**

### 5. 给模型看的材料,只放它需要填的东西(白名单瘦身)

证据清单只给**引用号 + 选择依据**。撤掉 `document_id` / `locator` / `excerpt` 等后端字段。
**不许把后端字段跟着材料一起端出去。**

### 6. 私有引用号不得外泄

不进公共 schema / API / 持久化 / 日志 / 前端。

## 验收(怎么证明遵守了本决策)

任何触及此类边界的卡,必须给出:

1. 草稿 DTO 是私有类型、`extra="forbid"` —— 贴代码
2. 后端字段不出现在草稿 schema 上 —— 贴 schema
3. **确定性测试**(fake provider / 固定输入):模型给了后端字段 → **显式报错**(不是静默接受,不是静默丢弃)
4. 未命中 / 歧义 / 类型错各有可区分子码,且各有测试
5. 公共 schema export 零 diff —— 证明私有引用号没外泄

★ **真机复跑只作支持性观察,不作契约正确性的证明**(理由见下第 3 条)。

## 理由

### 1. 这是确定性错误,不是概率错误

若草稿 DTO 要求一个"本阶段不可能生成"的字段,那**重试只是在重复犯错**。加重试、加 few-shot、抬 token 预算,统统治不了它。

**确定性契约错必须先修,不能靠重试掩盖。**

修法顺序(R1 裁定,不得倒):**契约 → 稳定 ID → few-shot(按需) → retry。**

### 2. "多给点信息总没坏处"是错的

把后端字段一起端给模型,不是"多给信息",是**给了它一道没有合法答案的题**:不抄不合格;抄了又抄不齐整(漏栏、多栏、格式走样),按成品尺子一量,整份报废。

### 3. ★ 契约修好 ≠ 产品变好

534 修完:契约错 **7 → 2**,七个新 bridge 子码**全 0** —— **靶子打中了**。
但**成品率一分没涨**(41.7% → 41.7%):病灶转移到了下一个杀手(`depends_on_self` 由 1 升到 7)。
端到端成品率的真正上涨,是**后续那张依赖措辞卡**换来的,不是本决策换来的。

所以本决策是**必要条件,不是充分条件**。
分离契约,只是让后面的病**有机会露头** —— 它们本来就被 DTO 短路挡在门外,一直没机会被看见。

(★ 这一点当初由 R1 预言:"DTO 短路后,后面的毛病根本没机会露头"。原话应验。)

**别把"某项指标改善"当"产品变好"。永远看端到端那个数。**

### 4. 六次都是"个案修掉",所以第七次一定还会来

前五次每次症状不同(字段名不同、报错不同),每次都当个案修了,**规矩一直没落成文**。
这就是它能踩到第六次的原因。本决策存在的意义,就是**不让它有第七次**。

## 影响范围

- 所有"LLM 产出结构化内容 + 后端补全"的边界,**不限于 build_steps**
- 未来任何新建 DTO 的卡,**起草时即须做责任划线**
- R1 设计审的严重度校准清单:"草稿 DTO 复用公共模型"应作为**默认排查项**

## 是否可逆

✅ 技术上可逆(改回复用公共模型)。
❌ **但不应该。** 六次实证 + 一次量化(头号杀手),证据已经够了。
