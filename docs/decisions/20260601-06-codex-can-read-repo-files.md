# 20260601-06:Codex 能直接读取仓库文件,Task 文档可使用引用

## 状态
✅ 决议

## 背景

TASK-002 启动前,PM 与架构师(Claude)对齐"PM 把 Task 文档传给 Codex 的方式":

- PM 是把 Task 文档**粘贴到 Codex 聊天窗口**
- 但 Codex 同时**有仓库工作区访问权限**,可以自行 `cat` / `read` 仓库内任何文件

这意味着:Task 文档里写"详见 `docs/04_ENGINEERING_STANDARDS.md` 第 7 节"是有效的,Codex 会去打开那个文件读。TASK-001 验收结果证明了这一点(Codex 严格按 04 第 4/6/7/13 节实现了 `pyproject.toml` / `requirements-dev.txt` / `.env.example` / `Makefile`,无任何偏差)。

## 决策

### 1. Task 文档可以使用"路径 + 节号"引用

例(允许):

```
- 配置严格按 docs/04_ENGINEERING_STANDARDS.md 第 4 节
- .gitignore 内容对齐 docs/04 第 7 节
```

**不需要**把每条规范的原文复制进 Task 文档,Codex 会自己去读源文件。

### 2. 引用必须给路径,不能只说编号

❌ 不允许:"按 04 第 7 节"(歧义,可能找不到)
✅ 允许:"按 `docs/04_ENGINEERING_STANDARDS.md` 第 7 节"

理由:6 份核心文档都在 `docs/` 下,显式路径让 Codex 无需猜测。

### 3. 例外:5 类教学输出格式(05 文档)

`docs/05_EXPLANATION_STYLE_GUIDE.md` 的 5 类输出 schema(A 项目总览 / B Block 讲解 / C .m 讲解 / D 问答 / E 不确定回答)是**高频被引用**的"模板",未来涉及讲解输出的 Task,**应在 Task 文档里直接内联对应类型的 schema 片段**,避免 Codex 反复跳转 + 减少误读风险。

简单引用(如"必须带 citations")仍可用路径方式。

### 4. 新决策日志 / 新规范的传达

PM 在仓库新增决策日志(如本文件)后,**无需特意提醒 Codex**,在 Task 文档里引用其路径即可。Codex 会读。

### 5. 不适用范围

- **新 Claude 会话(本对话外的架构师切换)**:Claude 默认看不到仓库,PM 仍需把核心文档贴进会话上下文(这就是当前会话的开头做法,继续保持)
- **AI 二审(GPT 等)**:同 Claude,不直接读仓,需要 PM 贴文档

## 理由

1. **减少 Task 文档体积**:不必每个 Task 都把规范原文复制一遍,Task 文档保持精简,聚焦"本 Task 要做什么"
2. **降低规范漂移风险**:Task 文档不重复规范原文,规范升级时只改源文件,不必扫所有 Task 文档同步
3. **TASK-001 已验证可行**:Codex 实战中正确读取并实现了 02 / 04 的所有要求,机制可信

## 影响范围

- 所有未来 Task 文档的写作风格
- 架构师交接文档(下次新 Claude 接手时,本决策也要写进交接文案)
- AI 二审材料准备(二审 ≠ Codex,需要单独打包文档)

## 是否可逆

✅ 完全可逆。如果未来发现 Codex 实际并不可靠地读取引用文件,可改回"重要约束必须内联"模式。
