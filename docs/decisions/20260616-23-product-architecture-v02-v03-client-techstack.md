## 2. 决策

### 2.1 v0.2 能力路线锁定

**主能力**(决策 22 § 4.8 第 ii 选项 / roadmap v2 § 4 已规划,本决策固化):

- **多文档融合**:从 v0.1 "单主资料"扩展到"一包异构资料"(论文 + 参考文献 + 师兄笔记 + 教材章节 + 草稿)
  - 处理三种情况:互补(A 给方程、B 给参数表)/ 重复(选证据更强)/ 冲突(明示分歧让用户判断)
  - 跨文档证据追溯(沿用 PaperEvidenceEntry 双源 + 文档来源标注)
- **图片 OCR**:解决 v0.1 PoC 实测硬伤 — 同步发电机 docx 实测有 6 张图片且关键参数(电压等级、阻抗值)常常只在图里,文本抽不到
  - OCR 抽取图片中的参数标注 + 单位识别 + 数值定位
  - 减少 v0.1 走 MissingParameterPrompt 兜底的频率
- **6 类 project_type 子类扩**:每类内部分流(电气 → 电力系统 / 电机控制 / 电力电子分支),提高路线图针对性

**承诺边界**:
- 工作量减少目标:相对 v0.1 再省 ~10-15%(资料越多越省;单文档场景持平 v0.1)
- 仍是 R1 降级三层(稳交付路线图 / 尽力 .m 骨架 / 不承诺 .slx 成品)
- 不接 MATLAB Engine(留 v0.3)

**估时**:3-4 周(决策 22 § 3.3 缓冲段,序号 TASK-501 主线段后续 task)

### 2.2 v0.3 能力路线锁定 — MATLAB Engine 闭环 + 用户自托管

**核心质变**:从 v0.1/v0.2 的"开环建议"升级到"闭环陪练"。系统能看到学生本地 MATLAB 的报错 / 收敛状态 / 仿真波形,实地给闭环建议。

**关键架构选择 — 用户自托管路径**(本决策核心拍板):

| 维度 | 产品方托管 MATLAB(原方案,决策 22 § 1.6 暂缓) | **用户自托管 + 接口桥接**(本决策拍板) |
|---|---|---|
| MATLAB License 责任 | 产品方承担,涉及合规 | 用户自有(学校 License) |
| 云端成本 | MATLAB 进程吃 CPU,高 | 零 |
| 代码执行安全 | 沙箱要顶住任意用户代码,门槛高 | 用户本机跑自己代码,无需沙箱 |
| 并发问题 | 多用户共享云资源,要解决配额 / 排队 / 隔离 | 每用户用自己机器,无并发问题 |
| 实施门槛 | 高(决策 22 § 1.6 列为"单独评审") | 中等(标准 IPC + REST/WebSocket) |

**架构形态**:

```
用户本地 MATLAB ← Engine API → 客户端(轻 Add-on)
                                    ↓ HTTPS
                              mxa-tutor Web 后端 ← LLM API
                                    ↓
                              建议回传 → 客户端 → 用户
```

**v0.3 工作量减少目标**:相对 v0.2 提升至 **55-65%**(相对完全无 LLM 基线)

**与决策 22 § 1.6 衔接**:
- 决策 22 § 1.6 字面:"Engine 集成留 v0.3+(PM 内部表述"万一 matlab 找我麻烦")"
- 本决策**评审结论 = 用户自托管路径绕开 License / 沙箱 / 云成本三大顾虑**,v0.3 可以进入实施
- 决策 22 § 1.6 中"先支持用户上传运行结果 → 再支持结果解释 → 最后才考虑隔离运行 MATLAB"的渐进顺序 **被本决策更新**:跳过"隔离运行 MATLAB"步骤,直接走"用户自托管 Engine 桥接"

**估时**:3-4 周(决策 22 § 3.3 缓冲段;含轻 Add-on 开发 + 后端桥接 API + v0.3 评测样本积累)

**v0.3 拆 a/b 两阶段(GPT Pro R1 复审 A 建议采纳)**:

| 阶段 | 范围 | 验收门槛 |
|---|---|---|
| **v0.3-a** Add-on 连接 spike | Add-on 安装流程 + 1 条 error/status 从 MATLAB 发到后端 + 1 条建议回传到 MATLAB UI + 至少 2 个 MATLAB 版本兼容 | Add-on 装机 ≤ 1 分钟,跨版本连通率 ≥ 90% |
| **v0.3-b** 闭环陪练正式能力 | 报错解释 + 收敛状态解释 + 波形/CSV/MAT 结果解释 + case 评测 | 真实场景调通率 ≥ 50%,评测 case ≥ 5 个覆盖 6 类至少 3 类 |

**理由**:Add-on 不是普通 Web 功能,真实风险在**安装、版本兼容、本地权限、网络回连、错误采集格式、Scope 波形导出** — 这些都是 Web 后端不会遇到的工程不确定性。一锅炖入一个 task 把 spike 风险和闭环推理风险混在一起,失败时定位困难。拆 a/b 让 a 阶段先消化工程不确定性。

**v0.3 安全边界(GPT Pro R1 复审 B 建议采纳)**:

"用户自托管绕开云端任意代码执行"判断对**产品云端**成立,但 Add-on 仍会读取本地错误、变量、波形、文件路径,甚至可能间接传输用户工程信息。本决策固化 Add-on 数据边界:

- **默认不上传完整工程文件 / 原始 .slx / 原始代码**
- **每次上传错误日志、变量摘要、波形截图 / CSV / MAT 前需用户显式确认**(可设置"记住选择"但每次行为可见)
- **后端只接收最小必要诊断 payload**(变量数值 / 错误堆栈 / 波形数据点,不接收源文件)
- **本地 token scoped 到单用户单项目**,可随时撤销
- **日志不得记录用户本地绝对路径 / 源码片段 / 完整模型内容**

这些边界不冲突"用户自托管"判断,只是把 Add-on 数据边界补齐 — Add-on 仍是用户本地进程,但跟产品 Web 的通信 payload 受最小化约束。

**与 roadmap v2 原 v0.3 能力的差异**(K_30 同步澄清):
- roadmap v2 § 5 原版规划 v0.3 含**两个**能力:逆向调参(A2a,决策 22 § 1.2)+ MATLAB Engine 评估
- 本决策**将 v0.3 主能力锁定为 Engine 闭环 + 用户自托管**(单一主线,3-4 周容量已紧)
- **逆向调参从 v0.3 推迟到 v0.4+**;理由:v0.3 容量优先级给 Engine 闭环(决策 22 § 4.4 PoC 三发现指向 Engine 闭环是真正产品代差);逆向调参作为后续能力扩展,在 v0.4+ Electron App / 教师工作台同期评估
- roadmap v2 § 5 同步修订(本决策 § 5.1 触发)

### 2.3 v0.3 客户端形态 — 轻起步 + 中扩展 + 不做重

**三档对比已分析**(详见 PM 方向 sanity check 对话):

- **轻 = MATLAB Add-on**:学生 MATLAB 里多一个工具栏按钮;装一个 .mlx 文件 30 秒;不离开 MATLAB 环境
- **中 = Electron 桌面 App**:独立软件,内嵌浏览器 + 后台本地服务连 MATLAB Engine;像 GitHub Desktop / Cursor 那种
- **重 = 完整桌面 IDE**:对标 VS Code / Cursor,学生整个工作流在产品里

**PM 拍板路径**:

1. **v0.3 起步走轻**:2-3 周开发,装机率最高,学生迁移成本最低
2. **轻得到验证后做中**(预计 v0.4+):Electron App 做 Web 和 Add-on 都做不了的事(课题组工作区 / 多工程历史 / 离线模式 / 桌面通知)
3. **终态:轻、中两形态并存,用户按需选**:学生用 Add-on(单机仿真) / 课题组与工程师用 Electron(多工程协作)
4. **不做重**:5 年内任何阶段都不做完整 IDE

**理由**:
- 让电气专业学生离开 MATLAB IDE 不现实(MATLAB IDE 黏性极高,VS Code 都没法在 MATLAB 圈普及)
- 跟决策 22 § 1.1 "副驾,不替代"定位一致(副驾不应该让用户换工作环境)
- 4-6 个月 IDE 开发远超 v0.3 时间预算
- 维护成本指数级上升(语法高亮 / 调试器 / 自动补全这些 IDE 基础设施都要做)

**轻形态技术选型**:**MATLAB Add-on**(MATLAB 自己的插件机制,.mlx + .mltbx 打包),不走 VS Code Extension 路径(MATLAB 用户主战场是 MATLAB IDE 本身)

### 2.4 技术栈纪律 — 5 年内不自训模型

**判断**:5 人小团队 5 年内**不专门训练模型**。靠以下四件套支撑到 v1.0+:

1. **Prompt 工程** + 第三方 LLM API(Claude / GPT;成本随 API 价格下降逐步降低)
2. **RAG** + 知识库(领域专家规则 + 教师沉淀 + 评测样本累积)
3. **评测样本驱动**(类似 TASK-500 门槛 5 的 golden JSON 模式,持续积累)
4. **可选的 SLM 微调加固层**(v0.3+ 视情况;7B-13B 规模小模型,加固某些电气专业术语 / 公式识别不稳定的环节)

**前提条件**:
- LLM API 价格趋势继续下降(过去 18 个月已降 10-100 倍,趋势预期持续)
- 若 API 端价格反向上涨或某主流 API 断供,触发"自训"重新评估,但**不是默认路径**

**Training infra(GPU 集群 / 数据标注 / RLHF)在 5 年内不投入**。

### 2.5 落地路径 — 阶段验收门槛

| 阶段 | 时间 | 主能力 | 验收门槛(决定是否进下阶段) |
|---|---|---|---|
| **v0.1** | 当前 5 周 | paper-to-model 副驾基础设施 | 决策 22 § 10.4 五项前置硬门槛全部完成(TASK-500)+ TASK-501 主线落地 + 评测样本积累 ≥ 5 case |

| **v0.3** | 3-4 周 | MATLAB Engine 闭环 + 轻 Add-on + 用户自托管 | Add-on 装机流程 ≤ 1 分钟 + 真实场景调通率 ≥ 50%(学生卡点能闭环解决) |
