## 0. 一句话路线

paper-to-model 副驾按**可信度阶梯**推进,不按用户身份倒推堆功能:

```text
v0.1  单主资料 → 模型搭建路线图(稳交付三层 + 电机短路验证)
v0.2  多文档融合 + 图片 OCR + 扩子类(控制 / 信号处理)
v0.3  MATLAB Engine 闭环 + 用户自托管 + 轻 Add-on
v0.4+ 逆向调参(A2a) + Electron / 教师工作台按 v0.3 反馈评估
v1.0+ 截图理解 / 报告答辩 / 课题组工作区 / 平台化(沿用 v1 长期路线)
```

核心原则(沿用 v1 § 25 + 决策 22 R1 降级):

> 先让系统可靠地"据资料给出搭建路线",再追求"自动生成成品"。
> 每升一级,证据链更强,而不是只让"输出更长"。
> 副驾不替代:帮用户完成复现的主要认知工作,精确搭建 / 跑通 / 收敛由用户自己来。

## 2. 当前基线(决策 22 PoC 实测)

paper-to-model 不是从零起步。决策 22 § 4 PoC 已实测两个电机仿真工程包,确立 v0.1 的真实边界:

### 2.1 已验证(v0.1 稳交付锚点)

- 从资料 / 报告(docx 学生实验报告类)抽取"模型搭建配方"可行(5MW / 平衡节点 / 0.2s 故障 / ode15s / 1s 等纯文本配方)
- 形成 plan 层"搭建路线图 + 库选型建议 + 参数对应表 + 子系统拆分"可行
- 范围:电机 / 电力电子类(SimPowerSystems 路线)

### 2.2 未验证(v0.1 实施期 + v0.2 验)

- 纯论文 PDF → 状态方程 → `.m` 骨架的稳定链路(决策 22 § 4.7,异步机两篇 PDF 未深读)
- 控制 / 信号处理类资料(可能不用 powerlib、搭法不同)
- 多文档融合
- 图片中参数自动抽取(决策 22 § 4.8,docx 暴露参数常在图片里)

### 2.3 三个定生死的发现(决策 22 § 4.4,决定 R1 降级)

1. ground-truth 模型用 SimPowerSystems 专业库,非基础 Simulink block
2. 论文图示搭法 ≠ 实际成品搭法(论文给物理方程 / 框图,不是接线图;人复现做了大量论文没写的工程决定)
3. `.slx` 自动生成不可靠(实测非推测)→ **不承诺打开即跑成品**

### 3.3 v0.1 新增能力

- **文档解析**:PDF / docx → 结构化(摘要 / 公式 / 参数表 / 图表位置 / 伪代码)

## 5. v0.3:MATLAB Engine 闭环 + 用户自托管 + 轻 Add-on

### 5.1 目标(决策 23 § 2.2)

实现 paper-to-model 真正的产品代差 — 从 v0.1/v0.2 "开环建议"升级到 v0.3 "闭环陪练"。系统能看到学生本地 MATLAB 的报错 / 收敛状态 / 仿真波形,实地给闭环建议。

**v0.3 工作量减少目标**(相对完全无 LLM 基线):**55-65%**(质变 — 第一次出现"通用 LLM 没法直接替代"的代差)

### 5.2 核心架构选择 — 用户自托管路径(决策 23 § 2.2)

| 维度 | 产品方托管 MATLAB(原方案,本决策放弃) | **用户自托管 + 接口桥接**(决策 23 拍板) |
|---|---|---|
| MATLAB License 责任 | 产品方承担,涉及合规 | 用户自有(学校 License) |
| 云端成本 | MATLAB 进程吃 CPU,高 | 零 |
| 代码执行安全 | 沙箱要顶住任意用户代码,门槛高 | 用户本机跑自己代码,无需沙箱 |
| 并发问题 | 多用户共享云资源,要解决配额 / 排队 / 隔离 | 每用户用自己机器,无并发问题 |
| 实施门槛 | 高(决策 22 § 1.6 列为"单独评审") | 中等(标准 IPC + REST/WebSocket) |

**架构形态**:

```text
用户本地 MATLAB ← Engine API → 客户端(轻 Add-on)
                                    ↓ HTTPS
                              mxa-tutor Web 后端 ← LLM API
                                    ↓
                              建议回传 → 客户端 → 用户
```

### 5.3 客户端形态 — 轻 Add-on 起步(决策 23 § 2.3)

**v0.3 默认形态 = MATLAB Add-on(轻)**:
- 学生 MATLAB 工具栏多一个按钮
- 装一个 `.mltbx`(≤ 1 分钟,内含程序化 `.m` app),不离开 MATLAB 环境
- 桥接本地 MATLAB Engine + HTTPS 与 mxa-tutor Web 后端通信
- 跨平台靠 MATLAB 自己处理

**不在 v0.3 做**:
- ❌ Electron 桌面 App(中):**v0.4+ 视 v0.3 反馈决定**(详 § 6)
- ❌ 完整桌面 IDE(重):**5 年内不做**(决策 23 § 2.3)

### 5.4 与决策 22 § 1.6 衔接

**决策 22 § 1.6 原字面**:"Engine 集成留 v0.3+(PM 内部表述'万一 matlab 找我麻烦')"

**决策 23 评审结论**(本节固化):用户自托管路径**绕开 License / 沙箱 / 云成本三大顾虑**,v0.3 可以进入实施;**跳过决策 22 § 1.6 中"先支持用户上传运行结果 → 再支持结果解释 → 最后才考虑隔离运行 MATLAB"的渐进顺序中的"隔离运行 MATLAB"步骤**。

### 5.5 v0.3 不含逆向调参(从原 v0.3 推迟到 v0.4+)

**决策 23 § 2.2 K_30 同步澄清**:

- 原 roadmap v2 § 5 把"逆向调参 + Engine 评估"并列作 v0.3 能力
- 决策 23 将 v0.3 主能力**锁定为 Engine 闭环 + 用户自托管**(单一主线,3-4 周容量已紧)
- **逆向调参从 v0.3 推迟到 v0.4+**;理由:v0.3 容量优先级给 Engine 闭环(决策 22 § 4.4 PoC 三发现指向 Engine 闭环是真正产品代差);逆向调参作为后续能力扩展,在 v0.4+ 同期评估

### 5.6 验收标准

- Add-on 装机流程 ≤ 1 分钟(关键产品体验门槛)
- 真实场景调通率 ≥ 50%(学生卡点能闭环解决)
- 评测样本积累 v0.3 case ≥ 5 个(覆盖 6 类 project_type 至少 3 类)
- **不达标不进 v0.4**(沿用决策 22 § 10.4 准入纪律)

- L1 学生陪练(v0.1-v0.2 已覆盖)
- L2 课题组工作区(v0.3+ 中 Electron 配套)
- L3 教师备课工具(v0.3+,教师免费 + 学生付费分成)
- L4 工业 to B(v1.0+,先内容合作后工具采购,决策 24 § 2.4)
- **to B 资源 ≤ 20% 硬边界**:to B 内容合作研发投入 ≤ 总研发资源 20%,不得挤占 v0.3 Engine 闭环主线(决策 24 § 2.4)

**跨行业扩展**(决策 24 § 2.3):
- 顺序:电气 → 电力系统 → 新能源 / 电力电子 → 自动控制 → 机械(v1.0+)→ 化工/土木/建筑(3 年内不做)
- 模式:**把电气做透,再用同一套架构去找下一个垂类合作伙伴**;终态 = 垂类教育 AI 平台,每个垂类有自己运营方
- **不是"做更多行业",是"做更深的电气 + 平台开放给其他垂类教师 / 工程师运营"**

**远期野心**(决策 24 § 2.5,5 年视角):
- AI 深度融入工科教育行业,**不止电气垂类**
- 跨行业扩展 + 平台化运营,**不是单团队全行业覆盖**
- 详 宪法 v3.1 § 1.1

## 7. 跨版本架构原则(沿用 v1 § 17 + 决策 22 红线)

### 7.1 三层不混(v1 § 17.1)

```text
Parser 还原(工程 / 论文)
中间层组织结构(ProjectGraph / PaperGraph)
LLM 讲 + 生成 plan
```

不让 LLM 直接猜结构。新增能力先进结构化层,再进讲解 / 生成层。

### 7.2 paper 不污染 MCS 契约(决策 22 § 5.2 + 决策 21)

- `features/paper/` 不 import `features/overview/` / `features/explanation/` 私有结构
- 跨 feature 共享只在 `core/` 公开 contract 层(沿用决策 18 ProjectOverview 下沉模式 / 决策 21 EvidencePack boundary)
- 禁止修改既有 MCS schema / service / prompt
- PaperGraph vs ProjectGraph 扩展二选一:以 02 v3.0 delta 拍板为准,TASK-501 派单前必须固化为一个方向,不留二选一(GPT 联审 P1)

### 7.3 所有回答可追溯(v1 § 17.3 + 决策 22 双源)

证据类型可新增(paper_section / equation_id / figure_id / user_supplied),但不取消证据原则。`document_extracted` 与 `user_supplied` 严格分开。

### 7.4 不确定是能力非失败(v1 § 17.4)

```text
有证据 → 回答
弱证据 → 保守回答
无证据 → 不确定
缺图片参数 → 提示用户补充(v0.1)/ OCR(v0.2)
需运行 → 要求用户提供结果(v0.1/v0.2);**v0.3 起经 Add-on 桥接用户本地 MATLAB Engine 跑**(用户自托管,决策 23 § 2.2)
```

### 7.5 升级不破接口(v1 § 17.5)

TextProvider / Retriever / ProjectStore / 向量存储接口尽量稳定;换模型 / 换实现只改 adapter。
